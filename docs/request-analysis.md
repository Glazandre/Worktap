Responce Headers
Используется для указания исходного типа мультимедиа ресурса до применения какого-либо кодирования контента. Тип контента html, charset указывает, что кодировка стоит utf-8.
content-type: text/html; charset=utf-8; 

Директива запроса no-cashe предписывает кэшам проверять ответ на исходном сервере перед повторным использованием, директива no-store используют когда пользователи выполняют принудительную перезагрузку страницы, max-age=0 может привести к повторному использованию устаревшего ответа, когда кэш отключается от исходного сервера. must-revalidate решает эту проблему.
Cache-Control: no-cache, no-store, max-age=0, must-revalidate;

Эта политика стоит по умолчанию всегда и значит следующее, отправлять источник, путь к запросу и строку при выполнении запроса того же источника. Для запросов с несколькими источниками отправляйте источник, когда уровень безопасности протокола остается неизменным. Не отправляйте Referer заголовок в менее безопасные места назначения (HTTPS -> HTTP).
referrer-policy: strict-origin-when-cross-origin;

Request Headers
accept-encoding: gzip, deflate, br, zstd : запрос и заголовок ответа указывают на кодировку содержимого (обычно алгоритм сжатия), которую может распознать отправитель. Формат сжатия gzip, использует кодирование Лемпеля-Зива с 32-битным CRC, формат сжатия deflate, использует структуру zlib с алгоритмом сжатия deflate, далее формат сжатия, использующий алгоритм Brotli, далее идет формат сжатия, использующий алгоритм Zstandart.
Cache-control: max-age=Priority: u=0, i : указывает на то, какой приоритет клиент отдаент отправке ответа, содержащего запрошенный ресурс, по сравнению с другими запросами ресурсов по тому де соединению. Внутри параметр u (urgency) указывает значение приоритета для ресура, в данном случае значение 0, это наивысший приоритет.
